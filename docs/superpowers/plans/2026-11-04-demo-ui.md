# SupportIQ Demo UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Một giao diện local để nhập câu hỏi tiếng Anh và xem classifier, routing, evidence, bản nháp hoặc lý do chuyển nhân viên từ pipeline thật.

**Architecture:** FastAPI phục vụ một trang HTML/CSS/JavaScript cùng origin và API demo mỏng gọi `apps.core_backend.orchestration.pipeline_runner.PipelineRunner`. Model inference là service riêng đã có. Backend demo tạo context từ hồ sơ demo server-side, giữ run/history/feedback trong SQLite và không tự gửi câu trả lời hoặc thực hiện giao dịch.

**Tech Stack:** Python/FastAPI/Uvicorn, HTML/CSS/JavaScript thuần, SQLite, pytest/TestClient, kiểm tra trình duyệt thật. Dùng dependency hiện có khi đủ; không thêm React, Node build hoặc UI framework.

**Spec:** [Routing](../specs/2026-11-04-routing-design.md), [Semantic Retrieval](../specs/2026-11-04-retrieval-design.md), [Đề bài](<../../CHỦ ĐỀ 1.md>). Nội dung dưới đây là thiết kế demo đề xuất kèm kế hoạch hiện thực; người dùng hiện yêu cầu lập kế hoạch, chưa yêu cầu triển khai.

## Global Constraints

* Giao diện tiếng Việt, câu hỏi/chính sách/model tiếng Anh; ghi rõ phạm vi ngôn ngữ cạnh ô nhập.
* Local-only, bind127.0.0.1 mặc định; dùng dữ liệu giả lập đã xác nhận. Không coi context demo là cơ chế authentication production.
* Không bypass routing confidence/approval, evidence validity/ACL hoặc lỗi model để demo có kết quả đẹp.
* Không hiện `llm_called=true` từ runner như bằng chứng LLM thật: code hiện tạo chuỗi mẫu sau retrieval. Hiển thị `draft_kind=template` cho đường hiện tại; chỉ nhận `llm` nếu có provider execution evidence thực.
* Không mutation nghiệp vụ, không gửi câu trả lời ra khách, không gọi API trả phí trong phạm vi này. Feedback approve/edit/reject/escalate chỉ lưu thao tác nhân viên demo.
* Không thay weights, policy hay dữ liệu gốc; model/embedding load một lần, lỗi encoder không làm mất khả năng chuyển cấp.
* UI hiển thị dữ liệu backend thực, không random evidence/intent/metrics. Dữ liệu thiếu phải ghi “Chưa có”, không mặc định thành công.

## Review Focus

1. Client sửa customer/scope/order: API không tin quyền từ browser; dùng danh sách hồ sơ giả lập server-side và kiểm tra ownership — Task1.
2. Người dùng nhấn lại/retry: run ID giữ nguyên cho cùng submission, không tạo escalation lặp — Tasks1/3.

5. Backend/model chưa ready hoặc không có evidence: trạng thái lỗi/clarify/escalate vẫn dùng được, không mock thành draft — Tasks1/4.

## 1. Phạm vi màn hình

Một màn hình “SupportIQ · Bàn hỗ trợ demo”, nền sáng, chữ đậm dễ đọc, màu xanh trầm cho nút chính; màu trạng thái luôn có nhãn chữ. Không cần biểu đồ, landing page, đăng ký, quản lý model hoặc lựa chọn threshold.

Desktop hai cột: trái ô nhập yêu cầu, hồ sơ khách giả lập, loại câu hỏi chung/cá nhân và order selector nếu cần; phải kết quả. Mobile xếp dọc. Thanh đầu trang có trạng thái inference/retrieval và nhãn “Local demo”. Mặc định có ví dụ tiếng Anh để chọn, không tự chạy.

Kết quả theo thứ tự:

1. Hành động: bản nháp / cần bổ sung / chuyển cấp / xử lý thủ công, đội nhận và lý do tiếng Việt dễ hiểu.
2. Intent, top1 score/margin nếu có, model/policy version; score chưa calibration ghi rõ “điểm mô hình”.
3. Nguồn: doc/title/version, đoạn trích, thời điểm áp dụng nếu có; không chỉ hiện evidence_count. Không có nguồn thì không vẽ placeholder như nguồn thật.
4. Bản nháp có nhãn “Mẫu minh họa” ở đường template hiện tại; cho sửa và lưu approve/edit/reject/escalate feedback. Không có nút “Gửi khách”.
5. Chi tiết thu gọn: run ID, stage durations nếu đo được, reason codes. Lịch sử10 lượt gần nhất của session demo, không dump toàn bộ SQLite.

Trạng thái bắt buộc: empty, processing, success, clarify (hiện slots thiếu), escalated, manual fallback, service unavailable, API error, feedback saved/error. Nút chạy disabled trong lúc request pending; input/draft giữ nguyên khi lỗi để thử lại. Các nút có label, focus visible, errors liên kết form, status `aria-live`, keyboard/tab hoạt động.

Không có UI incumbent để kế thừa. Khi hiện thực, áp dụng design skills ở chế độ Operate, hoàn thiện brief/product context cần thiết trước code UI và xem ảnh trình duyệt desktop/mobile. Không mở rộng bước này thành dự án thiết kế thương hiệu.

## 2. File map và hợp đồng API

Create:

* `apps/demo/__init__.py`, `apps/demo/app.py`: app factory, static files, endpoints và runtime lifecycle.
* `apps/demo/service.py`: context mapping, run/result serialization, health và feedback.
* `apps/demo/store.py`: feedback/history/session isolation nếu store hiện có không đủ; không tạo duplicate escalation engine.
* `apps/demo/static/index.html`, `styles.css`, `app.js`.
* `apps/demo/README.md`: setup, khởi động2 service, dữ liệu/model cần có, giới hạn và xử lý lỗi.
* `tests/unit/test_demo_api.py`, `tests/integration/test_demo_flow.py`.

Modify runner chỉ để expose dữ liệu đã có: `evidence` list, prediction top_k/confidence/margin nếu thực có, missing_slots, `draft_kind`, errors và timing; giữ các key cũ để không phá tests/callers. Không sửa logic routing/retrieval ngoài lỗi chặn tích hợp được xác minh riêng.

Endpoints cùng origin:

* `GET /api/demo/health`: trạng thái từng dependency, model/policy version và draft capability; readiness không suy từ HTTP process alive.
* `GET /api/demo/profiles`: ID/tên giả lập và các order ID được phép; không trả phone/transaction/raw scope. Operator chọn profile ở local demo, backend resolve fixed context, không nhận tùy ý scope.
* `POST /api/demo/runs`: `{submission_id, profile_id, text, is_personal_lookup, order_id?}`; text1..2000 ký tự, submission UUID, profile/order hợp lệ. Server tạo request fingerprint; cùng ID+payload trả cached run, cùng ID khác payload409. Kết quả gồm run/decision/action/team/reasons/slots, prediction, sources, draft `{body,kind,hash}`, timing và versions.
* `POST /api/demo/runs/{id}/feedback`: `{action, draft_hash, edited_text?}`; action approve/edit/reject/escalate, validate current revision. Update immutable feedback event, không side effect gửi/giao dịch; escalation chỉ enqueue qua idempotent store hiện có nếu có quyền, không tạo đường lách mới.
* `GET /api/demo/history`: tối đa10 lượt của session local tương ứng; HttpOnly SameSite session cookie, không nhận raw run ID người khác để đọc feedback/history.

Ứng dụng localhost vẫn chặn cross-origin mutation, dùng same-origin/CSRF token và không mở wildcard CORS. Không log câu hỏi/PII nguyên văn mặc định. Các ví dụ tạo từ dữ liệu giả lập có thật trong fixture, không hard-code ORD-123 production.
